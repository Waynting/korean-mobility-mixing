## 2. 第二個編碼錯誤，以及它為什麼救了 4.48%

自由文字有、`Q5_8` 沒設的列共 **3,395**，逐最小碼拆開：

| 最小碼 | 列數 |
|---|---:|
| 1 家戶 | **3,296** |
| 3 教育設施 | 23 |
| 4 宗教設施 | 9 |
| 5 餐飲 | 67 |

（`3,395` 與 `3,296` 是寄出的信裡寫的兩個數，**在此之前沒有任何腳本產生它們**，現在有了。）

把這個錯誤修回去（有自由文字就補上 code 8），三個慣例是：

| 慣例 | 多地點率 | 筆數 | 家戶＋其他 |
|---|---:|---:|---:|
| 不算殘留旗標（primary） | **4.4769%** | 5,989 | 2.7867% |
| 逐字（`p27` 已發表） | 10.5325% | 14,090 | 3.3773% |
| **逐字，修正後的檔案** | **12.9859%** | 17,372 | 5.7574% |

修正**照定義動不了** primary（有自由文字又有真碼的列，殘留旗標本來就被丟掉；只有自由文字
的列從 0 碼變 1 碼，還是單地點）——腳本 assert 了這一條。

**這就是換掉理由的地方。** `p57` 說「因為描述子寫單選，所以殘留旗標是改編碼」，那句前提死了。
新的理由是：**在他們自己說要發的那份檔案上，每一列有自由文字的都帶 code 8，所以逐字規則數的是
「有沒有打字」，不是「有沒有第二個地點」。** 逐字慣例在正確的檔案上失去意義，primary 不變。

代價是它只能當**下界**報：作者明說 8+x 有可能真的是兩個地點。所以要報的是
**4.48%（下界）到 12.99%（上界）**，中間不可回復。

## 4. code 1 兼含他人住宅，值多少

**為什麼這件事會咬人。** panel 規則取**最小的**碼，所以只要 `Q5_1` 有設就一定落 H，
去親戚家的接觸跟待在自己家一起被丟出 W+E。而被動側的 `dest_attr` 是**旅行者自己的
야간상주지**（`p21_rho.py` 開頭那段、`phase1a-manual.md`），所以「去別人家」在被動側是
**E 目的地、留在 W+E 裡**。同一件事，兩側分到不同的面板——回信把這件事從猜測變成確定。

五個臂，全部只在 `panel == "H"` 的列裡選：

| 臂 | 規則 | 移動筆數 | 佔全部接觸 |
|---|---|---:|---:|
| `letter_four` | 寄出的信自己引的四個字串 | 1,361 | 0.98% |
| `kinship` | 宣告的親屬詞表 | 2,901 | 2.17% |
| **`any_free_text`（primary）** | code 1 的列只要有自由文字 | **4,605** | 3.44% |
| `s6_household` | 在 Table S6 的 Household 清單裡 | 2,570 | 1.92% |
| `s6_other` | 有自由文字但不在該清單裡 | 2,035 | 1.52% |

前三個**跑之前就宣告**，巢狀所以構成夾擠。`any_free_text` 是 primary，因為它**完全不需要
對韓文字串做判斷**：依回信，有自由文字就代表受訪者沒選那個現成的「家戶」選項、答案是被回填的。

後兩個是**第一次跑完之後才加的**，加的理由寫在腳本裡：**Table S6 是作者自己的對照表**
（2026-09-01 從描述子的 SI 取得，那份檔案不在 figshare deposit 裡；
`eda/chae_tableS6.json`，81 筆，PDF sha256 `4bdee869…`）。它的成員不是我們挑的，
這就是「加一個臂」和「把一個臂放寬」的差別。**`kinship` 照原樣留著**——Table S6 證明那個
猜測漏了東西，而一個被證明是壞猜測的宣告臂，是關於那個猜測的證據，不是刪掉的理由。

### Table S6 自己也不完整，而這一條是量出來的、而且推翻了我原本的讀法

`s6_other` 這個名字原本要講的是「真的兩個地點的那些列」。**量出來不是。**
它的最上面是 `큰집`(114)、`외할아버지댁`(86)、`친가`(86)、`외할머니집`(57)、`아들집`(50)、
`외가`(44)、`친가댁`(40)、`친할아버지댁`(36)、`처가집`(28)、`시부모님댁`(27)——
全部是住宅，而 Table S6 就是沒列。

所以腳本多算一個**診斷**（不餵給任何被報告的 assortativity）：`s6_other` 裡有多少列的
字串以 **집／댁／자택** 結尾。答案是 **1,045 / 2,035**。於是：

- `s6_household` = 2,570 是「非本人自宅的住宅」的**下界**，不是那一類本身；
- `s6_other` 是**混合**，不是一個類別；
- 4,605 列裡至少 **3,615** 列指的是某個住宅，剩下約 990 列才是真的第二地點。

回信說「戶外那段只公布了一部分」，這裡量到的是**Household 那段也是**。
這件事值得回信告訴他們——他們已經說要修 CSV 了，SI 的表也一樣不完整。
