1. **`results_p40.json` 的下游清單裡，`eda/README.md:226` 這個行號本來就失準。**
   那句「465 人證不出……」在動我之前是 261 行、現在是 263 行，不是 226。
   這是 `p40` 那一輪就寫錯的，不是本輪造成的（本輪只讓它再偏 2 行）。
   沒有改的理由：`results_*.json` 唯讀。要修的話是下一次跑 `p40` 時修，
   或者乾脆讓清單存 grep 樣式而不是行號。
   `p31_report_audit.py` 那八個行號（325-326、338-340、289-301、307-308／320-321、
   187-194、461-463、476-482／517-519、493-499）本輪**逐一驗過仍然指到同一段程式碼**——
   新增的兩塊都落在 584 行與 1085 行之後。

2. **`emit_table()` 的來源清單掃不到 f-string 組出來的檔名。**
   那段的註解說「`load()` 之外還掃原始碼裡的字面檔名，才不會漏掉 `p34` 兩個面板、
   `p37` 與磁碟清單」，但實際的正規式 `results_[A-Za-z0-9_]+\.json` 對
   `f"{LIVE}/results_{name}.json"` 一個都比不到，所以那四個檔從來沒有進過來源清單。
   本輪新加的 `p39/p40/p41` 是走 `load()`，有進清單。
   沒有改的理由：那是生成檔的**出處說明**，不是閘門檢查項，修它會再動一次帳本內容，
   而本次的授權範圍是「加守備、不改值」。列在這裡，等下一輪一起修。

3. **08-21 的信本身沒有寫閘門項數。** 三個項數仍然只由 08-19 那封信與 README 承載。
   把項數拆成「每封信守自己的兩個數」需要在一封要寄出去的信裡寫一段閘門自述，
   那是為了滿足檢查而改信的內容，方向反了。所以項數維持成**跨文件的總數**，
   由既有的兩處散文承載，`p31` 裡也把這個取捨寫成註解。

4. **`p41` 的 `p_count_at_least`、`permutation.mc`、`placebo.cyclic_shift` 沒有入閘。**
   信裡明白說蒙地卡羅那個 5.0e−6「只進附錄，不報成顯著性」，
   循環位移安慰劑「有一半是退化的」。守一個信裡刻意不承重的數字沒有意義，
   要守的話應該守那句退化性陳述（`shift_k_near_degenerate_with_k_plus_6`），
   而那是下一輪把安慰劑寫進正文時的事。
