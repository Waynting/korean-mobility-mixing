# Phase 52 — R₀ 掃描重跑在修正後的全國臂上：7 個變 5 個

腳本 `eda/p52_r0nat.py` → `results_p52.json`。`--boot35 200`（預設，而且 args 就是答案）。
`results_p45.json` 與 `results_p40.json` 都不重跑、不可能動。

**一句話結論：老師 8/24 要拿「20 個判定裡 7 個隨 R₀ 翻」當主張三改寫的主要證據，
而七個裡有六個是全國格——整個掛在剛被修掉的那條臂上。重跑之後是 **5 個**。
句子的結構完全沒變（判定確實隨 R₀ 翻、2.5 確實是最友善的那一端），只是數字是 5。**

---

## 1. 為什麼非重跑不可

`p45_r0.py:112-129` 用 `pops[ym]`（首爾）約化每一份調查矩陣。`p45` 的 flips：

```
202312|national  1.2 / 1.5 / 1.8
202402|national  1.2 / 1.5 / 3.5
202402|seoul     3.5
```

七個裡六個是全國格。主張三要靠它改寫，所以它得先站在對的人口向量上。

## 2. 配對，而且這次連拔靴那一半都能逐位錨

`p45` 的 45.3 **不是**共用串流：`p45_r0.py:262-266` 每個 (月, scope, R₀) 從一條封閉公式
自己開一條 rng。所以與 `p40` 的 40.2 不同，這裡每一個區塊都獨立可重現。
而抽樣只依賴 rng 與受訪者陣列，人口向量是之後才在 `symmetrise` / `optimal_allocation` /
`final_size` 裡進來的——所以用首爾向量重跑一個區塊，必須逐位重現 `results_p45.json`。

⚠️ `p45` 自己的 docstring 說它的拔靴半「只能在蒙地卡羅誤差內比對」。那句話對的是 45.4
（對 `p40` 的比較，那**是**共用串流）；對 45.3 自己不成立。本階段用了這一點。

**三個錨，全是逐位的：**

| 錨 | 內容 | 結果 |
|---|---|---|
| 52.0a | `p45` 45.1 的 12 個確定性量（buy_first ＋ 兩個 between-tau × 四格） | 全部相符 |
| 52.0b | 整條 point 曲線：12 R₀ × 4 格 × 8 個量 = **336 個數** | `worst 0.0` |
| 52.0c | 重放一整個 200 次抽樣的拔靴區塊（202312\|national @ 2.5） | `worst 0.0` |

52.0c 只放一個區塊：十個全放會讓執行時間加倍而換不到新資訊，一個都不放則慢的那一半
完全沒被檢查。

**首爾兩格不重算**，直接沿用 `results_p45.json`——它們的向量本來就沒錯，重算只會在
沒有差別的地方製造差別。

## 3. 一個必須宣告的建模選擇

被動矩陣仍然是首爾的（那是既有限制）。但 `optimal_allocation(Cpd, ..., pop, ...)` 需要一個
人口，而評估世界換成全國之後有兩種讀法：被動方的規劃者用首爾人口（一個只有首爾資料的
規劃者會相信的），或用全國人口（人口結構是公開的，被動產品替代的是**混合**不是人口）。

**宣告：全國格一律用全國向量。** 年齡結構是統計廳公開的，沒有規劃者會弄錯；被動產品
替代的是「誰跟誰見面」。而且「規劃用首爾人口、評估用全國人口」等於替被動矩陣記上一個
沒有人會犯的錯，那會把 regret 往對本文有利的方向灌水。

```
202312|全國   1.2 / 1.5 / 1.8    不變
202402|全國   1.2                原本還有 1.5 與 3.5
202402|首爾   3.5                不變
```

掉的兩個本來就是最邊緣的——原本裕度 +1.6%（202402\|全國 @1.5）與 +1.1%（@3.5）。

## 5. ⚠️ 措辭：不能寫「在流行閾值附近最大」

四個格的 argmax 是 1.5／1.3／1.3／1.2，而網格從 **1.1** 開始，**R₀ → 1 的閾值本身沒有量過**。
正確的寫法是「1.2 到 1.5 這個區間最大」。圖 7 的底色帶到 1.5 為止、不往閾值延伸，
閘門也守著這兩條（「每一格的峰值都落在 1.2–1.5 之內」、「網格從 1.1 開始」）。
