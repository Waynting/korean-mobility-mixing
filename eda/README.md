## 資料放哪裡

程式碼、`results_pNN.json`、`fig/`、`cases/` 在 repo 裡;**`parquet/` 與 `derived/` 不在**(9.2 GB,已 gitignore)。
用 `KOREAN_DATA_ROOT` 指到外接硬碟,所有腳本跟著走:

```bash
export KOREAN_DATA_ROOT=/Volumes/YOUR_DRIVE/Korean     # 當次
cp .env.example .env && vi .env                        # 或寫死一次,新開的 shell 也吃得到
python eda/paths.py                                    # 印出各路徑解到哪、少了什麼
```

沒設就退回 repo 根目錄(2020 管線原本的位置),所以舊的跑法不會壞;export 的變數永遠蓋過 `.env`。
三棵樹也可以分開放——`KOREAN_PARQUET_DIR` / `KOREAN_DERIVED_DIR` / `KOREAN_RAW_DIR`——
擴充到 2026 之後有用:唯讀的來源 parquet 留在外接,衍生檔寫回內接的快碟。
硬碟沒掛載時 `connect()` 會直接報錯中止,**不會**讓你把空資料當成分析結果。細節見 [paths.py](paths.py)。

## 十八個 headline

1. **沒有日期欄位。** 最細單位是 `대상연월 × 요일 × 도착시간`。但每個格子聚合了哪些日期是**已知**的,所以政策曝光可以精確算出來 —— 這救回了劑量指派(D13)。
2. **`이동인구(합)` 是月內該星期的加總。** 不除以出現次數會讓結論反號(週二 Sep/Jan:原始 1.100,正規化後 0.880)。
3. **遮蔽只落在 20–44 歲**,0–19 與 65+ 恰為零。機制是門檻(值 < 3)碰上隨年齡變的擴大權重。
4. **KT 的年齡別覆蓋率是 U 型:** 0–9 歲 27.86×、45–49 歲 3.16×、80+ **9.43×**。資料本身沒有記載,從遮蔽門檻反推。
   ✅ **2026-08-17 已還原**到 `p9_quantum.py` §9.6,16 個齡組 × 4 欄共 64 個數字逐位重現 memo,無一失敗。
   80+ 原本寫 9.44×,那是**拿掉「至少 4 個星期幾」濾網**的版本;memo 的建構法給 9.43×,以後者為準。
   官方手冊自陳 10 세 미만與 80 세 이상「한 명의 이동이 열 배 가까이 보정되는 경우도 있다」,兩個獨立方法同一個答案。
5. **擴大權重跨 12 個月完全凍結**(CV ≤ 0.0123,中位恰為 0)。所以識別假設 A1 完全等價於「KT 各年齡層市占率全年不變」—— 負擔全部落在外部校準上。
6. **標籤漂移已封閉。** W 錨三月 0.826 → 七月 **1.003** → 九月 0.849。分類器漂移不可逆,這是行為軌跡。
7. **台北的形狀不變性在首爾不重現。** 十一個劑量水準上,分層形狀相關中位數 0.36–0.80(全 16 層)、0.51–0.90(25 歲以上),沒有一個切法接近 0.95 門檻。→ 走「聚合遮蔽」線。
8. ~~**效力衰減**~~ **已被十二月推翻。** 全年谷底是**十二月**(0.720)而非三月(0.767),而十二月同時是劑量最高、本地疫情最大的月份。殘差追的不是時間。
9. **保護性年齡梯度反轉(規格無關):** 二三月高齡減得比壯年多(75+ gap −0.12),之後轉正。**十二月管制更嚴、本地疫情是三月的 27.7 倍,75+ 移動量仍比三月高 14.3%,20–24 歲低 22.4%。**
10. **不可分離的是「風險」,不是「劑量」。** 加一個月趨勢就讓 75+ 的風險係數從 +0.117 翻到 −0.123,**6 個年齡組全部翻號**;但劑量係數 **0/6 翻號**,滿載規格下 75+ 仍是 −0.073(se 0.031)。n = 49 個乾淨格子撐不起把三者分開。
11. **年齡 × 地區的病例交叉在任何公開釋出裡都不存在** —— 但**「首爾只有全齡逐日」這半句是錯的**,
    2026-08-18 更正:**《서울시 코로나19 대응 소식지》有首爾逐日 × 9 齡帶**(晚期期數)與全期的累計分齡表,
    只是在 PDF 裡、不在任何機器可讀的開放集。仍然不存在的是**自治區 × 年齡**。
    見 [memo/spike-s1-seoul-age-cases.md](memo/spike-s1-seoul-age-cases.md)。
12. **月內跨星期的日曆外生變異只剩 1.64%。** 8 個月時是 4.67%、11 個月 1.82%、12 個月 1.64% —— 月份加得愈多,月固定效果吸收得愈乾淨,補資料不會讓它回升。**舊的 4.67% 在三份文件裡漏更新了兩輪。**
13. **主鍵不唯一。** 475,266 組重複鍵,每組恰好 2 列且**整列完全相同**,12 個月都有。
    原始 CSV 就有(ETL 逐檔對過 `wc -l`,不可能多寫),多半叢集在 ~100 萬行的匯出邊界。
    影響量體 0.034%,但格子層級的 join 或計數會被放大一倍。
    ⚠️ **2026-08-22 更正:「用 `DISTINCT` 去重,無損」是錯的。** `p43` 量出來,去重會讓官方
    자치구 對帳從 **+4.19e-06 惡化到 −1.52e-04**(36 倍且換號,兩側乾淨格都是 451),
    因為那些重複列在廠商產品的**兩個聚合層級上都被計入**。正確的規則是**逐路徑**:
    格計數與矩陣要去重,對帳官方檔的**量體不要**——`p36:387-398` 本來就是這樣寫的。
    見 [memo/phase43-datarecords.md](memo/phase43-datarecords.md)。
14. **99.03% 的邏輯網格沒有列 —— 缺列不是 0,是「無此觀測」。** 首爾內部的完整網格是
    86.98 億格/月,實際只有 8,403 萬列。稀疏幾乎全部來自最後一層(年齡 × 型別,條件填充率 2.8%);
    洞對本身幾乎全連通(179,776 對只有 224 對從未出現)。補成完整張量會憑空製造 99% 的零。
15. **`GU_NAMES` 可以定案了。** 用行政洞數當指紋:25 區的洞數向量與行政安全部名冊逐區吻合、
    0 個不符,總數 424,兩個極值也落對(송파구 27、금천구 10)。不再是「推斷未驗證」。
16. **「補值不是敏感參數」有例外。** 對量體指數確實不敏感(三種補值最多差 0.0066),
    但**性別比在 35–39 與 40–44 歲不可識別** —— 35–39 的 F/M 是 1.403 / 1.040 / 0.831,跨過 1.0。
17. **掉的是自由裁量行程與夜間,不是通勤也不是距離。** EE(기타→기타)十二月掉到 0.525,
    HW 只到 0.858;平日深夜佔比 10.7% → 6.5% 而尖峰時刻 12 個月紋風不動(08/18 시);
    量體加權平均移動時間全年只在 51.5–56.7 분之間游走(< 10%),遠小於量體的 29% 跌幅。
18. **六月是一個免費的風險安慰劑。** 六月與七月劑量完全相同(1.00),但六月首爾本地確診是五月的 2.0 倍,而移動量沒下降(0.929 → 0.934 → 0.946)。同劑量安慰劑也從一對變成 May/Jun/Jul 三角(25 歲以上 Jul/Jun 最大偏離 1 僅 2.3%)。
